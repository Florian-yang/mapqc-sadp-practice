# v0.2设计走查

原计划11/1，实际走查11/2。检查对象为目标结构、职责及接口，以下是设计推演，不是业务功能运行结果。

| 需求或场景 | 目标调用与检查 | 走查结论 |
| --- | --- | --- |
| F1 读GeoJSON与文本 | 视图提交路径，控制器调用LoaderRegistry，得到MapDocument后替换会话 | 解析与窗口分开；坏文件应保留旧会话，11/2实现验证 |
| F2 显示与选择位置 | 视图绘制文档，矢量点击转数据坐标，文本选择转行号，再交控制器 | 绘制坐标与领域位置有边界，11/3验证 |
| F3 登记与编号 | 控制器接收输入，调用会话登记规则校验并登记，通知视图刷新 | 编号不放在窗口；已有编号续接与空值处理待11/4验证 |
| F4 保存与重开 | 控制器调用仓储；重开先解析并比对每条记录的document_key，保存成功后再更新状态 | 失败不能替换有效记录或旧文件，11/5验证 |
| F5 关键字查询 | 控制器只把当前地图记录交给ErrorSearchService，视图显示结果及位置 | 换地图清除记录和查询结果，11/6验证 |
| E1 新增PNG | 注册新MapLoader，必要时增加文档字段与视图显示分支 | 登记、仓储、查询的接口可沿用，实际改动待11/7核对 |
| 领域隔离 | 领域模型及查询服务不导入Qt或具体文件访问构件 | 当前是设计约束，后续按实现检查导入依赖 |
| 部署与范围 | 图中构件运行在一台PC、同一进程；本机读写，无服务端 | 满足当前离线限制；未引入网络实现或未来功能代码 |
